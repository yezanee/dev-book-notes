## 20.1 원격 서버를 쓰는 이유

원격 서버를 쓰는 동기는 보통 두 가지입니다. 더 강력하고 유연한 실행 환경이 필요하거나, 다른 IP 주소가 필요한 경우입니다.

### 20.1.1 IP 주소 차단 방지

- 스크레이퍼는 헤더, 브라우저 정보 등 거의 모든 것을 위장할 수 있지만 IP 주소는 사실상 속일 수 없습니다. 패킷을 위조할 수는 있어도 스크레이핑은 응답을 받아야 하므로 의미가 없습니다.
- 사이트 운영자들은 대부분 사람과 봇을 구별하는 데 집중하고, IP 차단은 최후 수단으로 씁니다. IP 차단에는 세 가지 문제가 있습니다.
    - 차단 리스트 관리가 번거롭고, 자동화하더라도 누군가는 감시해야 합니다.
    - 패킷마다 리스트를 대조하는 비용이 쌓이기 때문에, 관리자들은 256개 주소 대역을 통째로 막는 식의 규칙을 만들곤 합니다.
    - 의도치 않은 피해가 생깁니다. 저자의 대학 시절, 한 학생의 부정 투표 프로그램 때문에 기숙사 전체 IP가 디그(Digg)에서 차단되었고, 정작 그 학생은 서버만 옮겨버렸습니다.
- 그럼에도 IP 차단은 여전히 가장 널리 쓰이는 방어 수단입니다.

### 20.1.2 이동성과 확장성

- 대규모 수집은 집 컴퓨터의 대역폭과 저장 공간을 넘어설 수 있습니다.
- 무거운 작업을 다른 컴퓨터에 맡기면 내 컴퓨터는 자유로워지고, 전원이나 네트워크 걱정 없이 어디서든 결과를 확인할 수 있습니다.
- 한 대로 감당이 안 되면 여러 컴퓨터가 사이트 집합을 나눠 수집하고 같은 DB에 저장하는 분산형 컴퓨팅으로 나아갈 수 있습니다. 원격 서버 실행은 그 첫 단계입니다.

## 20.2 토르

- 토르(어니언 라우터)는 자발적으로 참여하는 서버들로 이루어진 네트워크입니다. 트래픽이 여러 계층의 서버를 거치며 암호화되므로, 중간 서버 하나를 감청해도 출발지와 내용을 알기 어렵습니다. 경로상의 모든 서버를 추적해야 하기 때문입니다.
- 인권 운동가나 내부 고발자들이 많이 쓰고 미국 정부의 후원도 받지만, 불법 행위에도 쓰여 감시 대상이기도 합니다.
- **주의점**: 토르는 IP를 바꿔줄 뿐 완전한 익명성을 보장하지 않습니다.
    - 토르를 쓰면서 지메일에 로그인하고 검색하면 그 정보로 신원이 드러납니다.
    - 2013년 하버드 학생이 시험을 피하려고 토르로 폭탄 위협 메일을 보냈는데, 해당 시간대 캠퍼스에서 토르에 접속한 컴퓨터가 한 대뿐이라는 사실만으로 특정되었습니다.
- 공식 사이트에서 설치해 실행하면 되고, 트래픽이 전 세계를 돌기 때문에 속도가 느려집니다.

### 20.2.1 파이삭스(PySocks)

- 프록시 서버로 트래픽을 돌리는 단순한 모듈이며, 토르가 기본 포트 9150에서 실행 중이어야 합니다.
- 핵심은 SOCKS5 프록시를 기본값으로 지정하고 소켓을 교체하는 두 줄입니다.

```python
socks.set_default_proxy(socks.PROXY_TYPE_SOCKS5, "localhost", 9150)
socket.socket = socks.socksocket
```

- icanhazip.com은 접속한 클라이언트의 IP만 보여주는 사이트라 테스트에 유용합니다. 출력된 IP가 원래 IP와 달라야 성공입니다.
- 셀레니움을 쓴다면 파이삭스 없이 크롬 옵션에 `-proxy-server=socks5://127.0.0.1:9150`을 추가하면 됩니다.

## 20.3 원격 호스팅

결제 수단을 쓰는 순간 익명성은 사라지지만, 서버가 더 빠르고 토르 계층을 거치지 않아 속도가 크게 개선됩니다.

### 20.3.1 웹사이트 호스팅 계정에서 실행

- 명령줄 접근이 없어도 웹 인터페이스로 스크립트를 실행할 수 있습니다. 리눅스 호스팅이면 파이썬이 대개 설치되어 있습니다.
- 웹호스팅은 보통 cPanel을 제공하며, 아파치 핸들러에 `.py` 확장자를 cgi-script로 등록하면 파이썬 스크립트를 CGI로 실행하고 그 결과를 브라우저에 보냅니다.
- 스크립트를 올리고 퍼미션을 755로 바꾼 뒤 해당 URL에 접속하면 실행됩니다.
- 아무나 실행하지 못하게 하려면 추측하기 어려운 URL을 쓰고 링크를 노출하지 않거나, 비밀번호나 토큰을 요구하게 만듭니다.
- 단점은 스크레이핑이 끝나기 전까지 페이지가 뜨지 않아 몇 분, 몇 시간이 걸릴 수 있다는 점입니다. 실시간 확인이 필요하면 실제 서버가 필요합니다.

### 20.3.2 클라우드에서 실행

- 클라우드는 물리 컴퓨터 단위가 아니라 처리 능력 단위로 과금하며, 작업이 여러 컴퓨터에 나뉘어 실행됩니다. 비용은 요구치가 가장 높은 시점 기준으로 산정되며, 아마존 스팟 인스턴스처럼 시간보다 비용을 중시하는 옵션도 있습니다.
- 메모리, 처리속도, 저장공간 우선 옵션을 고를 수 있습니다. 스크레이퍼는 메모리를 많이 쓰지 않으니, 연산이 많은 작업(자연어 처리, 이미지 인식, 경로 탐색)은 처리 속도를, 대량 수집과 분석은 저장 공간을 우선하면 좋습니다.
- 집필 시점 기준으로 구글 f1-micro는 시간당 약 0.9센트, 아마존 EC2 마이크로는 약 0.8센트 수준이고, 두 회사 모두 상당한 무료 체험을 제공합니다.
- 입문자에게는 디지털오션을 추천합니다. 인스턴스를 드롭릿이라 부르며 시간당 0.6센트부터 시작하고, 생성하면 IP와 로그인 정보를 이메일로 줍니다.
- 인스턴스를 만들면 IP, 사용자 이름, SSH 키를 받고, 이후는 직접 소유한 서버와 같습니다. 하드웨어 관리가 필요 없다는 점만 다릅니다.
- SSH 키 다루기가 익숙하지 않다면 구글 클라우드의 브라우저 기반 SSH 터미널이 편리합니다(그림 20-1).

### 20.3.3 미래를 향해

웹 기술이 바뀌어도 스크레이핑에 필요한 사고방식은 그대로라며, 프로젝트마다 스스로 던져야 할 질문을 제시합니다.

- 지금 해결하려는 문제는 무엇인가?
- 어떤 데이터가 도움이 되고 어디서 찾을 수 있나?
- 사이트는 그 데이터를 어떻게, 코드의 어느 부분에 표시하나?
- 데이터를 어떻게 정확히 가져올까?
- 더 유용하게 만들려면 어떻게 처리하고 분석해야 할까?
- 더 좋게, 빠르게, 견고하게 만들려면 어떻게 해야 할까?

도구 하나하나를 넘어 조합해서 큰 문제를 푸는 능력이 중요하며, 저자는 인터넷을 사용자 인터페이스가 부실한 거대한 API로 보라고 마무리합니다.

## 20.4 웹 스크레이핑 프록시

- 이 시장은 진입 장벽이 낮아 경쟁이 치열하고 뚜렷한 대표 주자가 없는 혼잡한 상태입니다. 장비와 전기 비용이 막대해서 무료 서비스는 앞으로도 나오기 어렵습니다.
- 프록시 서비스는 내 요청을 대신 전달하고 응답을 돌려주는데, 일부는 요청을 잠시 저장했다 보내기 때문에 1분 이상 걸리기도 합니다. 따라서 하루 중 여러 시간대에, 쓰려는 기능별로 요청을 보내 응답 시간을 측정해 평가해야 합니다.

### 20.4.1 스크레이핑비(ScrapingBee)

- 자바스크립트 렌더링, 헤드리스 브라우저, IP 우회에 특화되어 있고, 문서가 잘 정리되어 있으며 클릭과 복사만으로 요청을 만드는 생성 도구가 있습니다.
- `app.scrapingbee.com/api/v1/`에 `api_key`와 `url`을 파라미터로 GET 요청하는 방식입니다. `pip install scrapingbee`로 SDK를 설치할 수 있고, 응답은 requests의 응답 객체와 같은 형태입니다.
- **크레딧 시스템**: 기본 요청은 1크레딧이고, 고급 기능은 5에서 75크레딧까지 소모합니다.
    - 무료 체험 1,000크레딧, 유료는 월 50달러에 150,000크레딧부터 시작하며 대량 구매 시 크레딧당 비용이 크게 낮아집니다.
    - JS 렌더링이 기본으로 켜져 있어 5크레딧이 들기 때문에, 필요 없으면 `render_js`를 `false`로 꺼서 같은 크레딧으로 5배 더 요청할 수 있습니다.
- 봇용 IP를 막는 사이트에는 프리미엄 IP(소규모 통신사의 주거용 IP)를 쓸 수 있고, 요청당 75크레딧인 스텔스 IP도 있지만 프리미엄 대비 실질적 이점은 불분명하다고 평가합니다.

### 20.4.2 스크레이퍼API(ScraperAPI)

- 깔끔한 REST API를 제공하며, 비동기 요청과 웹훅이 특징입니다. 기본 요청은 1크레딧이며, SDK는 `pip install scraperapi-sdk`로 설치합니다.
- 저자는 SDK 유무를 서비스 선택의 우선 기준으로 삼지 말라고 조언합니다. 몇 줄짜리 클래스로 누구나 직접 SDK를 만들 수 있기 때문입니다.
- 아마존 제품, 구글 검색 결과를 위한 자동 파싱 기능이 있고, 이런 요청은 5크레딧입니다. 결과는 출판사, ISBN 등이 담긴 구조화된 JSON으로 옵니다.
- **비동기 요청**
    - `async.scraperapi.com/jobs`에 POST로 작업을 생성하며, 이때 키 속성명은 `api_key`가 아니라 `apiKey`입니다.
    - 100ms 미만으로 응답하고, 응답에는 작업 ID와 결과를 조회할 `statusUrl`만 들어 있습니다.
    - 결과 조회 URL은 UUID만으로 보안이 되므로 API 키가 필요 없고, 결과는 최대 4시간 또는 가져갈 때까지 보관됩니다.
- 비동기 요청과 웹훅은 추가 비용이 없어 대규모, 장시간 프로젝트에 유용하며, 성공과 실패를 확인할 수 있는 대시보드도 제공합니다.

### 20.4.3 옥시랩스(Oxylabs)

- 리투아니아 대기업으로 SERP와 상품 페이지 스크레이핑에 중점을 둡니다. 다른 서비스보다 사용이 까다롭습니다. 제품마다 주간 무료 체험이나 구독으로 활성화해야 하고, 제품별로 별도 자격 증명을 만들어야 합니다.
- `realtime.oxylabs.io/v1/queries`에 HTTP 기본 인증과 함께 POST하며, 일반 용도는 `source`를 `universal`로 지정합니다.
- 같은 설정으로 아마존 URL을 넣으면 지원하지 않는 URL이라는 에러가 납니다. 아마존은 이커머스 스크레이퍼API를 따로 구독하고 `source`를 `amazon`으로 바꾼 뒤 해당 자격 증명을 써야 합니다.
- `parse`를 `True`로 설정하면 가격, 재고, 제목 등이 담긴 JSON을 받습니다. target.com 같은 일반 도메인도 `universal`과 `parse`를 함께 써서 파싱할 수 있지만, 일부 필드(예: description)에서 파싱 에러가 나기도 합니다.
- **커스텀 파서**: 필드와 XPath 선택자를 옥시랩스 형식의 JSON 파일로 정의할 수 있습니다. 하지만 이는 스크레이퍼의 비즈니스 로직 자체라서, 다른 서비스로 옮기면 쓸모없어져 재사용성 측면에서 문제가 됩니다.
- 옥시랩스의 제품은 기능이 아니라 요청 대상 도메인 기준으로 나뉩니다. 또 지원 도메인 관리가 허술한 경우도 있습니다. 예를 들어 SERP API가 바이두와 빙을 지원한다고 하지만 파싱 템플릿은 없고, 검색 엔진을 지정하는 기능만 있습니다.
- 저자는 비판의 목적이 특정 회사를 비난하려는 것이 아니라 평가 기준을 보여주려는 것이라고 밝힙니다. 광고와 실제 기능을 비교하고, 대상 고객층을 먼저 보며, 때로는 문서보다 API 호출 구조가 제품 구성을 더 잘 보여준다고 조언합니다.
- 옥시랩스는 프록시 IP 공급업체로 유명하며, 요청 단위가 아닌 GB 단위로 과금합니다. 집필 시점 기준 저용량 모바일 IP는 GB당 22달러(역자 주: 번역 시점 9달러), 대용량 주거용 IP는 GB당 8달러입니다.

### 20.4.4 자이트(Zyte)

- 이전 이름은 스크레이핑허브이며 2010년에 설립된 오래된 회사입니다. 2019년부터 웹 데이터 추출 서밋을 주최하고, 채용, 부동산, 제품 정보 같은 데이터를 직접 판매하거나 구축 컨설팅도 합니다.
- 스크레이피(Scrapy) 오픈 소스의 메인테이너로, 스크레이피 클라우드를 제공합니다. 깃허브 저장소나 명령줄 클라이언트로 프로젝트를 배포하면 스파이더가 대시보드에 추가되고, 클라우드에서 실행, 모니터링, 결과 다운로드를 할 수 있습니다.
- API는 `api.zyte.com/v1/extract`에 POST하며, 기본 인증에 사용자 이름과 비밀번호 대신 자이트 키만 보냅니다.
- 응답 본문이 HTML이나 JSON이 아니라 base64로 인코딩된 문자열이라 `b64decode`로 디코딩해야 합니다. 이 방식 덕분에 이미지 같은 바이너리도 쉽게 받을 수 있습니다.
- **자동 추출 API**: AI로 페이지 필드를 감지해 JSON으로 돌려줍니다(`pageType`을 `product` 등으로 지정). 기사와 제품 유형 사이트에서 잘 동작하고, base64가 아닌 일반 응답을 줍니다.
    - 문서에 이전 도메인 `scrapinghub.com` 주소가 남아 있으므로, 도메인이 바뀌어도 쉽게 수정할 수 있게 코드를 유연하게 짜라고 권합니다.
- **스마트 프록시 매니저**: IP 관리를 시스템이 대신하며, 세션 동안 같은 IP를 유지하다가 차단되면 자동으로 다른 IP로 전환해 자연스러운 트래픽을 만듭니다.
    - requests의 `proxies`에 키를 넣은 프록시 주소를 지정하고 `verify`에 CA 인증서 경로를 주어야 합니다.
    - `verify=False`로 검증을 끌 수도 있지만 권장하지 않습니다.
- 스크레이피 크롤러는 `scrapy-zyte-smartproxy`로 통합할 수 있습니다.
- 대략 1달러당 프록시 요청 1,600회, API 요청 12,000회 수준에서 시작하고(역자 주: 현재 요금은 공식 문서 확인 필요), 스크레이피 클라우드는 무료 티어와 월 9달러 프로페셔널 티어가 있어 상대적으로 저렴합니다. 저자는 이를 스크레이피 사용과 자이트 플랫폼 통합을 장려하는 전략으로 봅니다.
