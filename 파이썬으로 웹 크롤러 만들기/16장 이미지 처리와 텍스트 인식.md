## 16.1 라이브러리 개관

- **필로(Pillow)**: PIL에서 갈라져 나와 파이썬 3를 지원하는 이미지 처리 라이브러리입니다. 블러 같은 필터, 마스크, 픽셀 단위 변형을 쉽게 적용할 수 있고, 이 장에서는 OCR 전처리 용도로 씁니다.
- **테서랙트(Tesseract)**: 구글이 후원하는 오픈소스 OCR 엔진으로, 정확도와 유연성이 높고 새로운 폰트나 유니코드 문자를 학습시킬 수 있습니다.
    - 명령행 프로그램인 테서랙트와, 이를 감싼 파이썬 래퍼인 파이테서랙트(pytesseract)를 구분해서 씁니다.
    - 설치: 맥은 `brew install tesseract`, 리눅스는 apt, 윈도우는 인스톨러를 사용합니다. `tesseract --list-langs`로 설치된 언어 모델과 tessdata 경로를 확인할 수 있습니다.
    - 파이테서랙트가 테서랙트를 못 찾으면 `pytesseract.pytesseract.tesseract_cmd`에 경로를 직접 지정합니다.
- **파이테서랙트 주요 함수**
    - `image_to_string`: 인식된 텍스트를 반환합니다.
    - `image_to_boxes`: 문자별 경계 박스 좌표를 반환합니다.
    - `image_to_data`: 신뢰도 점수, 페이지/행 번호, 박스 등 전체 데이터를 반환합니다.
    - `output_type`으로 딕셔너리(`Output.DICT`)나 바이트(`Output.BYTES`) 형태로 받을 수 있습니다.
- **넘파이(NumPy)**: 단순 OCR에는 필요 없지만, 테서랙트 훈련이나 신뢰도 가중 평균 계산 등에 쓰입니다.
- 이 장은 파이테서랙트, 명령행 테서랙트, `subprocess`를 통한 테서랙트 실행을 섞어 씁니다. 파이테서랙트만으로는 안 되는 기능이 있기 때문입니다.

## 16.2 형식이 일정한 텍스트 처리

**형식이 일정한 텍스트의 조건**은 표준 폰트 하나로 작성되었을 것, 행 구분이 명확하고 열화나 어두운 부분이 없을 것, 수평으로 정렬되어 있을 것, 이미지 밖으로 잘리지 않았을 것 등입니다. 일부는 전처리(그레이스케일, 밝기 조정, 자르기, 회전)로 해결되지만 근본적인 한계는 훈련으로만 넘을 수 있습니다.

**깨끗한 이미지 vs 지저분한 이미지**

- 깨끗한 Arial 텍스트는 기호 하나 정도만 틀리고 거의 정확히 인식됩니다.
- 블러, JPG 압축 열화, 배경 그레이디언트가 섞이면 그레이디언트가 진해지는 지점부터 텍스트가 잘리고 마지막 글자들도 틀립니다.
- `tesseract 파일명 -`처럼 출력 파일 대신 대시를 쓰면 결과를 터미널에 바로 출력합니다.

**임계점(threshold) 필터 전처리**

- `image.point(lambda x: 0 if x < 143 else 255)`로 픽셀을 흑/백으로 나눠 회색 배경을 제거합니다.
- 일부 문장부호는 사라지지만 인식률은 크게 좋아집니다. 다만 r과 i가 붙어 n으로 읽히는 식의 오류는 남습니다.
- 테서랙트의 가장 큰 약점은 밝기가 일정하지 않은 배경이며, 테서랙트의 자동 보정보다 필로로 직접 전처리하는 편이 낫습니다.

### 16.2.1 이미지 자동 조정

- 이미지마다 최적 임계점이 다르므로, 임계점을 일정 간격으로 바꿔가며 OCR을 돌리고 가장 좋은 결과를 고르는 방식입니다.
- 평가 기준은 인식된 글자 수와, 글자 수로 가중 평균한 신뢰도(`image_to_data`의 `conf` 값 사용)입니다.
- 예제에서는 80부터 200까지 5씩 올리며 시험했고, 140과 145에서 글자 수가 가장 많았으며 145의 신뢰도가 더 높았습니다. 실험으로 찾은 143과 거의 일치합니다.
- 글자 수가 많다고 무조건 정확한 건 아닙니다. 한 글자를 두 글자로 쪼개거나 잡티를 글자로 읽을 수 있으므로, 신뢰도에 더 비중을 두거나 신뢰도와 글자 수를 곱한 값으로 평가하는 등 기준을 다듬을 수 있습니다.
- 이 방식은 임계점 외의 다른 필로 필터에도, 여러 변수를 동시에 조합하는 데에도 응용할 수 있습니다.
- 단점은 CPU 시간입니다. 탐색 범위를 경험적으로 좁히거나(예: 130~180), 처음엔 큰 간격으로 훑고 유망한 구간만 촘촘히 찾는 방식으로 줄일 수 있습니다.

### 16.2.2 웹사이트 이미지에서 텍스트 스크레이핑

- 셀레니움으로 아마존 책 미리보기를 열어 페이지 이미지를 수집하고, 각 이미지를 내려받아 테서랙트로 읽는 예제입니다.
- 흐름: 미리보기 버튼 클릭 → iframe 로딩 대기 후 전환 → 페이지 렌더러 로딩 대기 → `data-page` 속성을 가진 div 안의 img 수집 → `urlretrieve`로 다운로드 후 OCR.
- 큰 글씨와 산세리프 폰트일수록 인식이 잘 되며, 책 본문은 거의 완벽하게 읽힙니다.
- 오류 대응:
    - 고유명사는 단어 목록에 추가하고, 일반 사전 단어와 대조해 교정합니다.
    - I를 1로, vi를 w로 읽는 식의 예측 가능한 패턴은 치환 후보 목록을 만들어 처리합니다.
    - 단어 딕셔너리, 마르코프 체인, n-그램 분석으로 더 자연스러운 구절을 추측할 수 있습니다(12장 참고).
- 코드가 아마존 사이트 구조에 강하게 의존하므로 구조가 바뀌면 동작하지 않을 수 있습니다.

## 16.3 CAPTCHA 읽기와 테서랙트 훈련

**배경**

- CAPTCHA는 컴퓨터와 사람을 구별하는 완전 자동화된 튜링 테스트의 약어입니다.
- 구글은 사람조차 풀기 어려워진 텍스트 기반 reCAPTCHA를 2017년에 중단했고, 지금은 주로 소규모 사이트에서 쓰입니다.
- 원리상 품질 낮은 스캔본이나 손글씨를 읽는 것과 비슷해서 좋은 연습 재료가 됩니다.
- 기본 테서랙트로 U8DG CAPTCHA를 읽으면 u& DS처럼 엉뚱하게 나옵니다. 원인은 인식 능력 부족이 아니라 손글씨풍 폰트가 기본 학습 데이터와 너무 다르기 때문입니다.

### 16.3.1 테서랙트 훈련

**훈련 성능에 영향을 주는 요소**: 글자끼리 겹치는지, 폰트 변형이 있는지, 배경 방해 요소가 있는지, 글자와 배경의 대비가 강한지, 폰트가 일반적인지 등입니다. 겹침이 있으면 겹치지 않는 샘플을 쓰거나 전처리로 분리해야 합니다.

**필요한 샘플 수**: 문자당 약 10개가 권장되며, 변형이 크면 더 필요합니다. 학습에 실패하는 파일도 생기므로 여유분을 확보해두는 게 좋습니다. 표준 폰트라면 훈련 없이 먼저 써보는 것을 권합니다.

**1단계: 이미지 수집과 전처리**

- BeautifulSoup으로 CAPTCHA 페이지에서 이미지를 100개 내려받아 문자 샘플 400개를 확보합니다.
- `cleanImage` 함수로 검은 배경에 회색 글자를 흰 배경에 검은 글자로 반전(임계점 143)하고, `ImageOps.expand`로 흰 테두리 20px를 추가해 글자를 가장자리에서 떼어냅니다.

**2단계: 박스 파일 만들기**

- 박스 파일은 한 줄에 문자 하나와 그 경계 좌표 4개를 담습니다.
- tesseract-trainer 프로젝트의 `createBoxes.html`을 이용합니다. 파일명을 정답 문자열로 바꾸고(예: AK6F.png), 웹 앱에 올려 자동 생성된 박스를 드래그로 맞춘 뒤 .box 파일을 내려받습니다.
- 매우 지루하고 몇 시간 걸리는 작업이니, 끝나면 반드시 백업해두라고 합니다.

**3단계: trainer.py로 훈련**

- 디렉터리 구조: `data/cleaned`(전처리된 이미지)와 `data/box`(박스 파일).
- `TesseractTrainer(languageName, fontName, directory)`를 만들고 `runAll()`을 호출하면 전 과정이 자동으로 진행됩니다.
    - `createDirectories`: 결과 저장용 exp 등 디렉터리 생성
    - `createFontProperties`: 폰트명과 이탤릭/볼드 등 변형 여부(0/1)를 담은 font_properties 생성
    - `renameFiles`: 박스와 이미지 파일을 `언어.폰트.exp번호` 형식으로 변경
    - `createTrainingFiles`, `extractUnicode`: 학습 파일 생성 및 학습 가능한 문자 집합 확인
    - `runShapeClustering`, `runMfTraining`, `runCtTraining`: 글자의 기하 구조와 통계 정보를 담은 shapetable, pfftable, normproto 생성
    - `createTessData`: 모두 합쳐 최종 traineddata 파일로 컴파일

**4단계: traineddata 적용**

- `tesseract --list-langs`로 tessdata 경로를 확인하고 `TESSDATA_PREFIX` 환경 변수를 설정합니다.
- traineddata 파일을 그 디렉터리로 복사한 뒤 `tesseract -l captcha U8DG.png -`처럼 언어를 지정해 실행합니다.
- 결과: 훈련 전 u& DS였던 이미지를 훈련 후 U8DG로 정확히 인식합니다.

## 16.4 CAPTCHA 가져오기와 답 보내기

**이미지 기반 CAPTCHA의 공통 특징**

- 서버가 동적으로 생성한 이미지지만 일반 이미지처럼 내려받을 수 있습니다.
- 정답은 서버 DB에 있습니다.
- 대개 제한 시간이 있어서, 요청과 제출 사이 지연이 길면 실패합니다.

**봇 흐름**

1. 페이지를 BeautifulSoup으로 파싱해 폼과 함께 POST되는 숨겨진 토큰 값을 찾습니다.
2. 이 토큰이 CAPTCHA 이미지 파일명과 같으므로, `getCaptchaSolution`에서 이미지 URL을 조립해 내려받습니다.
3. `cleanImage`로 전처리하고, `subprocess.Popen`으로 훈련된 언어(`l captcha`)를 지정해 테서랙트를 실행합니다.
4. 출력 파일에서 공백과 줄바꿈을 제거해 답을 얻습니다.
5. 답이 정확히 4글자일 때만 `requests.post`로 폼을 제출하고, 아니면 오류 메시지를 출력합니다.

**실패 조건과 대응**

- 4글자를 못 뽑은 경우: 페이지를 다시 불러 재시도하면 됩니다. 제출 전이라 서버에 걸릴 가능성이 낮습니다.
- 제출했는데 틀린 경우: 실제 서비스라면 반복 실패 시 차단이나 추가 검증을 받을 수 있습니다.
- 성공하면 mail_sent 상태의 JSON 응답이 돌아옵니다.

**마무리**: CAPTCHA는 예전만큼 흔하진 않지만 여전히 쓰이고, 여기서 익힌 전처리와 OCR 기법은 이미지에서 텍스트를 뽑는 다른 상황에도 그대로 응용할 수 있습니다.
