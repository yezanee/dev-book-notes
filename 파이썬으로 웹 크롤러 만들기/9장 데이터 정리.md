### 9.1 미디어 파일

미디어 저장 방식은 두 가지입니다.

1. **URL(참조)만 저장**
    - 장점: 빠르고 대역폭과 저장 공간을 아끼며, 코드가 간단하고 호스트 서버 부하도 적음
    - 단점: 핫링크 문제, 미디어를 남의 서버에 의존, 원본 파일이 바뀌거나 사라질 수 있음, 실제 브라우저처럼 리소스를 받지 않으므로 사람처럼 보이기 어려움
2. **파일 자체를 다운로드**
    - `urllib.request.urlretrieve(url, 파일명)`으로 원격 파일을 내려받음

판단 기준은 그 파일을 나중에 실제로 열어볼지 여부입니다. 수집만 하고 볼 일이 없다면 URL만으로 충분합니다.

**전체 파일 다운로드 예제의 흐름**

- `findAll(src=True)`로 src 속성이 있는 태그를 모두 찾음
- `getAbsoluteURL`로 상대 경로를 절대 URL로 변환 (외부 링크는 제외)
- `getDownloadPath`로 원래 경로 구조를 유지하며 `downloaded` 폴더에 저장
- `os.makedirs`로 디렉터리가 없으면 생성

**주의사항**: 모르는 파일을 무작위로 받는 건 위험합니다. 악성 스크립트가 섞일 수 있고, 관리자 권한으로 실행하면 경로 조작(`../../usr/bin/python` 같은 파일명)으로 시스템 파일이 덮어써질 수도 있습니다. 권한이 제한된 계정에서 실행해야 합니다.

### 9.2 CSV로 저장

- CSV는 쉼표로 열을, 줄바꿈으로 행을 구분하는 단순한 형식
- CSV 파일을 그냥 받아서 저장만 할 거면 일반 파일처럼 다운로드하면 됨
- 파이썬 `csv` 모듈의 `csv.writer()`와 `writerow()`로 작성
- `open('파일', 'w+')`는 파일이 없으면 생성하고 있으면 경고 없이 덮어씀 (디렉터리는 자동 생성 안 됨)
- **HTML 테이블을 CSV로 변환**하는 게 대표적 활용: `table` → `tr` → `td/th` 순으로 순회하며 `get_text().strip()`으로 텍스트만 추출
- 한 번만 할 작업이라면 테이블을 복사해서 엑셀이나 구글 시트에 붙여넣는 게 더 빠름

### 9.3 MySQL

#### 9.3.1 설치

- 가장 널리 쓰이는 오픈소스 RDBMS로, 무료이고 확장성이 좋아 스크래핑 프로젝트에 적합
- 설치 방법: 리눅스는 `apt-get install mysql-server`, 맥은 설치 패키지나 Homebrew, 윈도우는 설치 관리자 (Setup Type에서 Server Only 권장)
- 접속: `mysql -u root -p`

#### 9.3.2 기본 명령어

- 키워드는 대소문자를 구분하지 않지만, 관례적으로 키워드는 대문자, 테이블/DB 이름은 소문자
- `CREATE DATABASE`, `USE`로 DB 생성 및 선택
- 테이블은 열 없이 만들 수 없음 (ERROR 1113)
- 열 정의는 이름, 타입, 추가 속성(`NOT NULL`, `AUTO_INCREMENT`)으로 구성되고 마지막에 `PRIMARY KEY` 지정
- `DESCRIBE`로 테이블 구조 확인
- `INSERT`에서 id와 timestamp는 직접 넣을 수 있지만 MySQL에 맡기는 게 좋음
- `SELECT`의 , `WHERE`, `LIKE '%...%'` 와일드카드 사용
- **`DELETE`/`UPDATE` 전에는 같은 조건으로 `SELECT`를 먼저 실행해서 대상 확인하기**

#### 9.3.3 파이썬과 통합

- 파이썬은 MySQL을 기본 지원하지 않으므로 `PyMySQL` 사용
- **연결 객체(conn)**: DB 연결, 커밋, 롤백, 커서 생성 담당
- **커서 객체(cur)**: 현재 사용 중인 DB 등 상태 정보와 마지막 쿼리 결과 보관, `fetchone()` 등으로 조회
- 하나의 연결에 커서 여러 개 가능
- **커넥션 누수 방지**: 사용 후 커서와 연결을 반드시 닫고, 스크래핑 루프는 `try...finally`로 감싸기
- **유니코드**: DB와 테이블, 열의 문자셋을 `utf8mb4` / `utf8mb4_unicode_ci`로 변경하고 연결 시 `charset` 지정
- 위키백과 랜덤 탐색 예제: `store()` 함수로 제목과 본문 첫 단락을 INSERT 후 commit

#### 9.3.4 데이터베이스 테크닉과 모범 사례

1. **모든 테이블에 자동 증가 id를 프라이머리 키로**: 스크래핑에서는 무엇이 고유할지 미리 알기 어렵기 때문
2. **인덱스를 잘 관리하기**: 자주 검색하는 열에 인덱스를 걸되 공간과 INSERT 비용이 늘어나므로, 긴 문자열은 앞 일부(예: 16글자)만 인덱싱하는 방법 활용
3. **정규화로 중복 줄이기**: 구절과 URL을 한 테이블에 반복 저장하는 대신 `phrases`, `urls`, `foundInstances` 세 테이블로 분리하면 대부분 정수 id만 저장하게 되어 용량이 크게 줄어듦
4. **타임스탬프 기록**: created, updated, deleted 같은 열로 변경 이력 추적

#### 9.3.5 여섯 다리와 MySQL

- 6장의 케빈 베이컨 문제를 분석 가능한 구조로 저장
- 링크는 페이지 A에서 B로 가는 관계이므로 `pages`(id, url, created)와 `links`(fromPageId, toPageId) 두 테이블로 설계
- 위키백과는 URL만으로 제목을 알 수 있어서 페이지를 방문하지 않고도 저장 가능
- 주요 함수
    - `insertPageIfNotExists`: 없을 때만 페이지 저장, 해당 id 반환
    - `insertLink`: 중복 링크 없이 저장해 무결성 유지
    - `loadPages`: 중단 후 재시작해도 이어서 수집할 수 있도록 기존 페이지 로드
    - `pageHasLinks`: 이미 수집한 페이지인지 확인
- `recursionLevel`이 5가 되면 멈춰서 스택 오버플로 방지
- 한계: 발견만 하고 방문 안 한 페이지를 구분하지 못하므로 재시작 시 누락 가능, `visited` 같은 플래그로 해결 가능
- 실제 경로 탐색은 12.2.1절의 방향성 그래프 문제에서 마무리

### 9.4 이메일

- 이메일은 SMTP로 전송되며, 파이썬에서는 `smtplib`과 `email` 패키지 사용
- `MIMEText`로 제목, 발신자, 수신자, 본문을 담은 메시지 객체 생성
- `smtplib.SMTP(호스트)`로 연결해 `send_message()` 후 `quit()`으로 연결 종료
- 예제: 한 시간마다 isitchristmas.com을 확인해서 NO가 아니면 메일 발송
- 응용: 사이트 다운 감지, 테스트 실패 알림, 품절 상품 재입고 알림 등
