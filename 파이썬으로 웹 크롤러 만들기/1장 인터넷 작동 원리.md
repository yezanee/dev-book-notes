### 1.1 네트워킹

**패킷 스위칭**

- 과거 전화망은 교환원이 물리적으로 선을 이어 발신자와 수신자 사이에 전용 회선을 만드는 방식이었습니다.
- 인터넷은 메시지를 순서가 매겨진 패킷으로 쪼개고, 각 패킷에 발신자와 수신자 주소를 담아 보냅니다.
- 같은 메시지의 패킷이라도 서로 다른 경로로 이동할 수 있고, 도착 후 원래 순서로 재조립됩니다.
- 비유: 옛 전화망은 단일 경로만 있는 집라인, 패킷 스위칭은 여러 차가 같은 도로를 공유하는 고속도로입니다.

**OSI 7계층**

1. 물리 계층: 전기 신호, 전압, 무선 전파 등으로 0과 1을 물리적으로 전달하는 방식. 물리 법칙과 전기 표준 영역입니다.
2. 데이터 링크 계층: 로컬 네트워크 안에서 기기 간 전송 방식. 패킷에 라우팅 정보를 씌운 단위를 프레임이라 하고, 오류 수정도 담당합니다. (역자주: 책 설명은 과거 허브 방식이고, 요즘은 L2 스위치가 목적지 MAC 주소를 보고 해당 포트로만 전달합니다.)
3. 네트워크 계층: 라우터를 통해 로컬 네트워크 경계를 넘어 원거리 목적지까지 패킷을 전달합니다. TCP/IP 중 IP가 여기에 해당합니다.
4. 전송 계층: 특정 애플리케이션끼리 연결하고 오류 수정과 재전송을 처리합니다.
    - TCP는 모든 패킷이 정확히 도착할 때까지 재요청하므로 파일 전송처럼 신뢰성이 중요한 곳에 씁니다.
    - UDP는 누락 패킷을 무시하고 흐름을 유지하므로 화상, 음성 통화에 적합합니다.
    - 포트 번호로 애플리케이션을 구분합니다. 예: `71.245.238.173:8080`에서 앞은 IP, 8080은 OS가 특정 애플리케이션에 할당한 포트입니다.
5. 세션 계층: 두 애플리케이션 사이의 세션을 열고 닫으며, 무엇이 전송됐는지 등 상태 정보를 유지합니다.
    - NOTE: 웹 개발에서 말하는 세션(브라우저에 저장되는 세션 변수)은 응용 계층 개념으로, OSI 세션 계층과는 다른 것입니다.
6. 표현 계층: 데이터를 애플리케이션이 쓸 수 있는 형식으로 변환하고 문자 인코딩, 압축을 담당합니다. JSON, HTML 같은 포맷이 여기 해당합니다.
7. 응용 계층: 변환된 데이터를 실제 기능에 활용합니다. HTTP(메서드, 상태 코드)가 대표적입니다.

웹 개발자는 주로 응용 계층에서 일하지만, 스크레이핑에서는 다른 계층의 개념도 필요합니다. 예를 들어 17장의 TLS 핑거프린팅 탐지는 전송 계층과 관련이 있습니다.

### 1.2 HTML

- 브라우저의 주 역할은 HTML 문서를 표시하는 것이고, HTML은 주로 ASCII로 인코딩된 일반 텍스트입니다.
- HTML은 XML의 특수한 형태입니다. XML이 태그, 내용, 속성, 값의 기본 개념을 정의하고, HTML은 어떤 태그와 속성을 어떻게 쓰고 브라우저가 어떻게 해석할지를 구체적으로 정합니다.
- 구성 요소
    - 여는 태그 `<html>`, 닫는 태그 `</html>`, 그 사이의 내용
    - 내용이 필요 없는 빈 요소 태그(자체 닫힘 태그): `<p />`
    - 속성은 `속성="값"` 형태: `<div class="content">`
    - 요소 안에 다른 요소가 들어가면 중첩 요소
- class는 여러 요소가 같은 값을 가질 수 있지만, id는 페이지 안에서 반드시 고유해야 합니다. 스크레이퍼가 요소를 찾을 때 이 차이가 중요합니다.
- 표시 방식은 브라우저 구현에 달려 있어 표준화가 중요하고, 현재 표준은 W3C가 관리합니다. 최신 태그 정보는 WHATWG의 HTML 명세에서 확인할 수 있습니다.

### 1.3 CSS

- CSS는 HTML 요소의 레이아웃, 색상, 위치, 크기 등 외관을 정의합니다.
- 선택자 문법
    - `h1 { ... }`: 모든 h1 태그
    - `h1#main-title`: id가 main-title인 h1 (`#`은 id)
    - `div.content`: class가 content인 div (`.`은 class)
    - `.content`: 태그와 상관없이 class가 content인 모든 요소
- CSS 위치: HTML의 head 안 `<style>` 태그에 직접 넣거나, `<link rel="stylesheet" href="...">`로 외부 .css 파일을 불러옵니다(일반적).
- 스크레이핑에서 CSS를 직접 쓸 일은 거의 없지만, 화면에 보이는 구조를 이해하려면 필요합니다. 예를 들어 HTML에는 있는데 화면에 안 보이는 요소는 `display: none`으로 숨겨져 있을 수 있습니다.
- CSS 선택자 문법은 이후 스크레이핑 도구에서 요소를 찾을 때 그대로 쓰이므로 기본 문법은 익혀두는 게 좋습니다.

### 1.4 자바스크립트

- 서버 사이드 코드: 서버에서 실행되어 페이지를 만들어 응답합니다(파이썬, 자바, PHP 등).
- 클라이언트 사이드 코드: 서버에서 전송되지만 브라우저에서 실행되며, 텍스트 변경이나 드래그 앤 드롭 같은 상호작용을 담당합니다.
- 과거에는 자바 애플릿, 플래시 등도 있었지만 별도 설치 없이 브라우저가 기본 지원하는 유일한 언어였던 자바스크립트만 살아남았습니다.
- 역사: 1990년대 중반 넷스케이프 내비게이터에서 탄생, 인터넷 익스플로러가 채택하며 표준화. 1996년 넷스케이프와 썬 마이크로시스템즈의 라이선스 계약으로 이름을 썼지만 자바와는 별개 언어입니다.
- HTML 삽입 방식: `<script>` 안에 직접 작성하거나 `src` 속성으로 외부 파일을 참조합니다.
- 스크레이핑 관점의 포인트
    - JS를 직접 작성할 일은 거의 없지만, `<script>` 안 변수에 JSON 형태의 데이터가 그대로 들어 있는 경우가 있어 바로 파싱할 수 있습니다(JSON은 15장에서 자세히).
    - JS가 `fetch`로 다른 URL에서 데이터를 가져오는 경우, 그 URL을 직접 요청하면 원하는 데이터를 더 쉽게 얻을 수 있습니다.
- 모든 동적 효과가 JS 때문은 아닙니다. CSS 키프레임 애니메이션처럼 HTML/CSS만으로도 일부 동적 변화가 가능합니다.

참고로 책의 fetch 예제에서 `console.log(response.json())`은 실제로는 데이터가 아니라 Promise 객체를 출력합니다. 실제 데이터를 보려면 `.then(res => res.json()).then(data => console.log(data))`처럼 한 번 더 이어야 합니다.

### 1.5 개발자 도구로 웹사이트 검사하기

- 개발자 도구는 스크레이핑의 필수 도구입니다. 책은 크롬 기준이지만 다른 브라우저도 사용법이 비슷합니다.
- 여는 법: 맥은 Option + Command + I, 윈도우는 Ctrl + Shift + I (사파리는 설정의 고급 메뉴에서 개발자 기능 표시를 켜야 함)
- **네트워크 탭**
    - 페이지 로딩 중 발생하는 모든 요청을 보여주며, 복잡한 페이지는 수십에서 수백 개 요청을 만들고 로딩 후에도 폴링 등으로 계속 요청하기도 합니다.
    - 요청마다 요청 URL, HTTP 메서드, 응답 상태, 헤더와 쿠키, 페이로드, 응답을 확인할 수 있습니다.
    - 브라우저와 똑같은 데이터를 받아오는 스크레이퍼를 만들 때 매우 유용합니다.
    - NOTE: 개발자 도구를 열어둔 상태에서 로드해야 요청이 잡히므로, 이미 로드된 페이지라면 새로고침해야 합니다.
- **요소 탭**
    - HTML 구조를 탐색하고 원하는 데이터를 감싸는 태그를 찾는 데 씁니다.
    - 페이지에서 우클릭 후 검사(Inspect)를 누르면 해당 요소로 바로 이동합니다.
    - 요소 탭에서 태그 위에 마우스를 올리면 페이지에서 해당 영역이 강조 표시됩니다.
