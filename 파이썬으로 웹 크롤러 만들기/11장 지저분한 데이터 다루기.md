## 11.1 텍스트 정리하기

위키백과 Python 문서의 본문(`mw-content-text` 안의 `p` 태그)을 추출한 뒤 아래 작업을 함수로 하나씩 만들어 적용함.

- **`[123]` 형태의 인용 표시 제거**: `strip_citations`, 정규식 `\[[0-9]*\]`
- **줄바꿈 처리**: `replace_newlines`, 줄바꿈을 지우지 않고 공백으로 바꿔서 문장끼리 붙어버리는 것을 방지
- **문장 단위 분리**: `split_sentences`, 마침표만이 아니라 마침표와 공백(`'. '`)을 기준으로 나눠서 `Python 2.5` 같은 소수점이나 코드 속 마침표에서 잘리지 않게 하고, `strip`으로 앞뒤 공백 정리
- **괄호 안 부연 설명 제거**: `remove_parentheses`
    - 처음의 `\(.*\)`는 코드 예제 속 괄호까지 지워버리고, 짝이 안 맞는 괄호가 있으면 다음 닫는 괄호까지 통째로 삭제될 위험이 있음
    - 그래서 허용 문자 종류를 제한하고 길이도 `{0,100}`으로 제한한 정규식으로 개선
- **그림/코드 설명 제거**: `remove_descriptions`, 새 줄에서 시작해 문자로만 이루어지고 콜론으로 끝나는 짧은 설명(`Hello world program:`)을 `\n[a-z A-Z]*:`로 제거
- **소문자 변환**: `make_lowercase`
- **문장 부호 제거**: `remove_punctuation`, 앞 단계들이 문장 부호에 의존하므로 반드시 마지막에 수행. `string.punctuation`의 각 문자를 `re.escape`로 이스케이프한 뒤 `|`로 연결해 정규식 생성
- **유니코드 정규화**: `normalize`, 웹 텍스트에 흔한 줄바꿈 없는 공백(`\xa0`, HTML의 `&nbsp;`) 같은 문자를 `unicodedata.normalize('NFKD', text)`로 정리

핵심 포인트

- **작업 순서가 중요함**: 문장 부호를 먼저 지우면 인용 표시를 찾을 수 없고, 소문자 변환과 부호 제거를 먼저 하면 문장을 나눌 수 없음
- **정규식은 함수 밖에서 미리 컴파일**: 함수 안에서 매번 `re.sub(r'...')`를 쓰면 호출마다 재컴파일됨. 상수(대문자 변수명)로 빼두면 속도도 나아지고 정규식에 이름이 붙어 문서화 효과도 있음
- **함수를 리스트에 담아 파이프라인으로 실행**: `text_operations` 리스트에 함수들을 순서대로 넣고 반복문으로 적용. 결과가 리스트가 되면(문장 분리 이후) 각 원소에 적용하도록 분기. 순서를 바꾸거나 단계를 추가/제거하기 쉬움

## 11.2 정규화된 텍스트 다루기

- **n-그램**: 텍스트를 n개 단어 단위 조각으로 나눈 것. 예제는 2-그램 사용
    - `getNgrams('web scraping with python', 2)` 결과는 `web scraping`, `scraping with`, `with python`
    - n-그램은 보통 문장 경계를 넘지 않으므로 앞 절에서 문장 단위로 정리한 결과를 사용
- **빈도 세기**: 리스트에 쌓기만 하면 중복이 많고 빈도를 알 수 없으므로 `collections.Counter` 사용
    - 리스트는 해시할 수 없어 Counter에 넣을 수 없음. 그래서 `' '.join(...)`으로 문자열로 바꿔 저장
    - `countNGramsFromSentences(cleaned, 2).most_common()`으로 빈도순 정렬. 결과 상위는 `in the`, `of the`, `such as`처럼 주제와 무관한 일반 표현이 차지함 (이런 것을 걸러내는 방법은 12장에서 다룸)
- **정규화를 확장할 때의 고민**
    - 철자는 달라도 같은 의미인 경우가 많음 (`Python 1st`와 `Python first`). 규칙을 늘릴수록 단어마다 확인해야 할 경우의 수가 늘어남
    - 하이픈 처리는 트레이드오프가 있음. 하이픈을 지워 한 단어로 붙이면 `all-too-common` 같은 구절이 뭉개지고, 공백으로 바꾸면 `co ordinated`, `ordinated attack` 같은 엉뚱한 n-그램이 생김
    - 정규화가 잘 되면 고유 n-그램 수는 줄지만 전체 n-그램 수는 줄지 않음. 빈도를 기록해두면 정리 알고리즘을 바꿨을 때의 효과를 확인하기 좋음

## 11.3 판다스로 데이터 정리하기

### 기본

- 판다스는 2008년 웨스 맥키니가 시작한 데이터 분석 패키지로 `pip install pandas`로 설치하고 관례적으로 `import pandas as pd`로 사용
- **주의**: 판다스 함수/클래스를 개별 임포트하지 말 것. `from pandas import array`처럼 쓰면 파이썬 내장 `array` 모듈이나 `min` 함수와 충돌할 수 있음. 예외적으로 `DataFrame`만은 표준 라이브러리에 없어서 직접 임포트가 허용되지만, 대부분은 `pd.DataFrame`으로 씀
- **데이터프레임**: 스프레드시트와 비슷한 객체로 항상 인덱스와 열 이름을 가짐 (지정하지 않으면 0, 1, 2... 자동 생성). 대규모 데이터에서는 리스트나 딕셔너리보다 속도와 메모리 면에서 유리
- `df.head(n)`으로 앞부분을 보기 좋게 출력 (기본 5행)

### 11.3.1 정리

위키백과 맥도날드 진출 국가 목록 CSV를 `pd.read_csv`로 읽어 정리하는 예제.

- **열 이름 변경**: `df.rename(columns={원래이름: 새이름}, inplace=True)`, `inplace=True`면 새 객체를 반환하지 않고 원본을 수정
- **필요한 열만 선택**: `df[['Order', 'Country', 'Date', 'Location', 'Outlets']]`
- **날짜 열 정리**
    - 열 하나를 선택하면 `Series`가 되고, `apply`로 각 값에 함수를 적용할 수 있음
    - 날짜 정규식 `[A-Z][a-z]+ [0-9]{1,2}, [0-9]{4}`로 찾은 것 중 첫 번째만 남긴 뒤 `pd.to_datetime`으로 실제 datetime으로 변환
    - 영국 행처럼 여러 날짜가 섞인 경우 첫 번째를 고르니 마침 정답(가장 이른 날짜)이 나왔지만 이는 우연. 빠르게 깨끗한 데이터를 만드는 것과 정확하고 미묘한 정보를 보존하는 것 사이의 균형을 판단해야 함
- **매장 수 열 정리**: `13,515[failed verification]` 같은 값에서 정수 정규식 `[0-9,]+`로 첫 숫자를 찾아 쉼표를 지우고 `int`로 변환
    - 단계가 여러 개면 람다보다 별도 함수로 분리하는 게 좋음. `try/except`로 예외 값을 출력해 따로 검토할 수 있기 때문

### 11.3.2 인덱싱, 정렬, 필터링

- **인덱스 설정**: `df.set_index(['Order'], inplace=True)`, 기존 인덱스를 버리고 Order 열을 인덱스로
- **정렬**: `df.sort_values(by=['Outlets', 'Date'], ascending=False)`. 정렬은 주로 탐색용이라 원본은 두고 결과만 받아보는 편이 유용함. 결과는 미국, 중국, 일본, 프랑스 순
- **필터링**: `df.query('Outlets < 100')`
    - 쿼리 문자열은 파이썬 문법과 달라서 `Date is not None`은 예외 발생
    - 빈 값 확인은 `Date.isnull()`, `Date.notnull()` 사용 (None과 NumPy의 NaN 모두 인식)
    - AND는 `&`, OR는 `|`
    - 날짜 비교 시 연도만 써도(`"1990"`) 동작할 만큼 관대하지만, 결과가 기대와 맞는지 항상 재확인 필요
