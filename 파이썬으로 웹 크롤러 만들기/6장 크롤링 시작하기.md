## 6.1 단일 도메인 내의 이동

웹 크롤링은 현재 페이지를 분석하고, 페이지에 존재하는 링크를 찾아 다른 페이지로 이동하는 작업을 반복하는 방식이다.

기본 흐름은 다음과 같다.

**페이지 요청 → HTML 분석 → 링크 추출 → 다음 페이지 선택 → 다시 요청**

예제에서는 위키백과의 한 페이지에서 시작해 다른 위키백과 페이지로 계속 이동한다.

### 내부 링크만 추출하기

HTML의 모든 `<a>` 태그를 가져오면 우리가 원하는 문서 링크뿐 아니라 개인정보처리방침, 연락처, 카테고리 등 불필요한 링크도 포함된다.

위키백과의 일반적인 항목 링크에는 다음과 같은 특징이 있다.

- `div#bodyContent` 내부에 존재
- URL에 `:`이 없음
- `/wiki/`로 시작

따라서 정규표현식을 사용하여 원하는 링크만 필터링한다.

핵심은 **웹사이트의 URL 구조에서 일정한 패턴을 찾아 필요한 링크만 선택하는 것**이다.

### 무작위로 페이지 이동하기

`getLinks()` 같은 함수를 만들어 현재 페이지의 내부 링크들을 가져온 뒤, 그중 하나를 무작위로 선택할 수 있다.

개념적으로는 다음 과정이다.

`현재 페이지 → 내부 링크 목록 → 임의의 링크 선택 → 해당 페이지 이동 → 반복`

이를 통해 하나의 사이트 내부를 계속 돌아다니는 간단한 크롤러를 만들 수 있다.

여기서 난수의 시작값인 **seed**를 현재 시간 등으로 설정하면 실행할 때마다 다른 탐색 결과를 만들 수 있다.

### 재귀를 이용한 반복 탐색

페이지마다 다시 링크를 가져와 다음 페이지를 탐색해야 하므로 재귀 구조를 사용할 수 있다.

하지만 종료 조건 없이 재귀 호출하면 문제가 발생한다.

- 무한 탐색 가능
- 같은 페이지를 반복해서 방문할 수 있음
- Python의 재귀 호출 제한에 걸릴 수 있음

따라서 실제 크롤러에서는 방문 기록과 종료 조건이 중요하다.

## 6.2 전체 사이트 크롤링

단순히 링크를 무작위로 따라가는 것과 **사이트 전체를 크롤링하는 것**은 다르다.

전체 사이트 크롤링에서는 보통 최상위 페이지에서 시작하여 내부 링크를 모두 탐색하고, 각 페이지에서 다시 발견되는 내부 링크를 계속 탐색한다.

즉,

**시작 페이지 → 내부 링크 탐색 → 새로운 페이지 탐색 → 그 페이지의 내부 링크 탐색 → 반복**

하는 구조다.

### 방문한 페이지를 저장하는 이유

크롤링 과정에서 동일한 페이지가 여러 곳에서 링크될 수 있다.

따라서 방문한 페이지를 저장하지 않으면 같은 페이지를 계속 크롤링하게 된다.

이를 해결하기 위해 `set`을 사용할 수 있다.

```
pages = set()
```

새로운 URL을 발견하면:

```
이미 방문했는가?
 ├─ YES → 무시
 └─ NO  → pages에 저장 → 해당 페이지 탐색
```

`set`을 사용하는 핵심 이유는 **중복을 허용하지 않으며 특정 URL의 방문 여부를 빠르게 확인할 수 있기 때문**이다.

### 전체 사이트 크롤러의 핵심 구조

개념적으로 보면 다음과 같다.

```
getLinks(page)
    ↓
현재 페이지 요청
    ↓
HTML 파싱
    ↓
내부 링크 검색
    ↓
방문한 적 없는 링크인가?
    ├─ 아니오 → 넘어감
    └─ 예 → pages에 추가
              ↓
          getLinks(newPage)
```

즉, 사이트의 링크 구조를 **그래프 탐색하듯 순회**하는 것이다.

### 전체 사이트에서 데이터 수집

크롤링의 목적은 단순히 페이지를 돌아다니는 것이 아니라 **각 페이지에서 필요한 데이터를 가져오는 것**이다.

예제에서는 위키백과 페이지에서 다음과 같은 정보를 가져온다.

- 페이지 제목
- 첫 번째 문단
- 편집 페이지 링크

중요한 점은 모든 페이지의 HTML 구조가 완전히 동일하다고 가정하면 안 된다는 것이다.

어떤 페이지에는 원하는 태그가 없을 수 있기 때문에 예외 처리가 필요하다.

```
페이지 접근
   ↓
원하는 요소 탐색
   ↓
요소가 존재하는가?
 ├─ YES → 데이터 추출
 └─ NO  → 예외 처리 후 다음 페이지
```

즉, 크롤러는 **HTML 구조 변화나 누락된 데이터에 견딜 수 있게 작성해야 한다.**

### 크롤링 시 주의할 점

사이트 전체를 크롤링하면 요청량이 매우 많아질 수 있다.

예를 들어 페이지마다 내부 링크가 여러 개 존재하면 탐색 범위가 빠르게 증가한다.

따라서 다음을 고려해야 한다.

- 이미 방문한 URL 중복 제거
- 탐색할 페이지 수 제한
- 예외 처리
- 서버에 과도한 요청을 보내지 않기
- 사이트의 이용 정책 및 `robots.txt` 확인
- 가능하다면 공식 API 사용

특히 대량의 위키백과 데이터를 사용할 목적이라면 HTML을 직접 크롤링하는 것보다 **Wikipedia API를 사용하는 것이 효율적일 수 있다.**

### 사이트맵 활용

사이트 전체 구조를 파악해야 하는 경우 직접 모든 링크를 따라가는 방법 외에 **사이트맵(sitemap)**을 활용할 수도 있다.

사이트맵은 웹사이트의 페이지 구조를 정리해 놓은 정보이므로 다음과 같은 작업에 유용하다.

- 존재하는 페이지 파악
- 사이트 구조 확인
- 누락된 페이지 탐색
- 전체 페이지 수 파악

## 6.3 인터넷 크롤링

앞에서는 하나의 도메인 안에서 이동했다면, 인터넷 크롤링에서는 **외부 링크를 따라 다른 도메인으로 이동**한다.

예를 들어:

```
사이트 A
   ↓ 외부 링크
사이트 B
   ↓ 외부 링크
사이트 C
   ↓
...
```

이를 위해 링크를 두 종류로 구분한다.

**내부 링크(Internal Link)**

현재 사이트와 같은 도메인으로 연결되는 링크.

**외부 링크(External Link)**

현재 사이트와 다른 도메인으로 연결되는 링크.

### URL 분석

URL을 분석할 때 `urlparse()`를 활용할 수 있다.

주로 확인하는 부분은 다음과 같다.

- `scheme` : `http`, `https`
- `netloc` : 도메인
- `path` : 도메인 뒤의 경로

예를 들어

```
https://example.com/careers

scheme = https
netloc = example.com
path = /careers
```

따라서 현재 페이지와 링크의 `netloc`을 비교하면 내부/외부 링크를 구분할 수 있다.

### 내부 링크 수집

`getInternalLinks()`의 역할은 현재 사이트와 같은 도메인의 링크만 가져오는 것이다.

판단 방식은 대략 다음과 같다.

```
링크의 netloc이 비어 있음
→ 상대 URL → 내부 링크

또는

링크의 netloc == 현재 사이트 netloc
→ 내부 링크
```

상대 URL이라면 현재 사이트의 `scheme`과 `netloc`을 붙여 완전한 URL로 만들어 사용할 수도 있다.

### 외부 링크 수집

`getExternalLinks()`는 반대로 현재 사이트와 다른 도메인의 링크를 가져온다.

```
링크의 netloc 존재
AND
링크의 netloc != 현재 사이트 netloc

→ 외부 링크
```

내부 링크와 외부 링크를 분리하면 크롤러가 **현재 사이트 안을 탐색할지, 다른 사이트로 이동할지** 결정할 수 있다.

### 외부 링크가 없는 경우

현재 페이지에 외부 링크가 없을 수도 있다.

이 경우 현재 사이트의 내부 링크 중 하나로 이동한 뒤 다시 외부 링크를 찾는다.

```
현재 페이지
   ↓
외부 링크 존재?
 ├─ YES → 외부 링크 하나 선택 → 다른 사이트 이동
 └─ NO  → 내부 링크 하나 선택
             ↓
         다시 외부 링크 탐색
```

이 구조를 반복하면 여러 사이트를 계속 이동하는 인터넷 크롤러를 만들 수 있다.

## 내부 링크 + 외부 링크 전체 수집

좀 더 완전한 크롤러에서는 두 작업을 동시에 수행한다.

```
현재 페이지
   ↓
├─ 내부 링크 수집
│     ↓
│   방문하지 않은 내부 링크 탐색
│
└─ 외부 링크 수집
      ↓
    처음 발견한 외부 링크 저장
```

이때 내부 링크와 외부 링크 모두 중복될 수 있으므로 이미 발견한 링크를 별도로 관리한다.

또는 전체 방문 페이지를 관리하는 `pages` 같은 집합을 사용할 수 있다.
