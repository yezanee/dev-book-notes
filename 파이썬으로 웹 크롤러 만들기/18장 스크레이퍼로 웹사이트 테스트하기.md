## 18.1 테스트 입문: 단위 테스트의 특징

- 하나의 단위 테스트는 구성 요소의 한 가지 측면만 검증합니다. 같은 구성 요소를 다루는 테스트는 보통 한 클래스로 묶습니다.
- 각 테스트는 완전히 독립적이어야 합니다. 준비와 정리를 테스트 스스로 하고, 다른 테스트의 결과나 실행 순서에 영향을 받으면 안 됩니다.
- 보통 어서션(assertion)이 최소 하나 들어갑니다. 예외가 나지 않으면 통과하는 식으로 실패 조건만 두는 경우도 있습니다.
- 테스트 코드는 메인 코드와 분리된 클래스와 디렉터리에서 관리합니다.

## 18.2 파이썬 unittest

표준 라이브러리라 별도 설치가 필요 없고, `unittest.TestCase`를 상속하면 다음 기능을 쓸 수 있습니다.

- 각 테스트 전후에 실행되는 `setUp`, `tearDown`
- 다양한 `assert` 메서드 (`assertEqual`, `assertTrue`, `assertIsNotNone` 등)
- 이름이 `test_`로 시작하는 메서드만 테스트로 실행

`setUp`과 `tearDown`은 클래스 전체에서 한 번이 아니라 테스트마다 매번 실행된다는 점을 기억해야 합니다.

**주피터 노트북에서 실행할 때**는 `unittest.main(argv=[''], exit=False)`로 호출합니다. 주피터가 넘기는 argv 인자와 테스트 종료 후 파이썬을 끄려는 동작이 커널과 충돌하기 때문입니다. 이어서 `%reset`을 실행하면 이전 실행에서 남은 테스트 클래스와 메서드가 메모리에서 지워져, 다음 실행 때 옛 테스트가 함께 돌아가는 일을 막을 수 있습니다.

### 18.2.1 위키백과 테스트

- BeautifulSoup으로 페이지를 가져와 제목(h1)이 Monty Python인지, 본문 div(`mw-content-text`)가 있는지 검사합니다.
- 페이지는 `setUpClass`로 한 번만 불러와 여러 테스트가 공유합니다.
    - `setUpClass`: 클래스 시작 시 한 번 실행되는 정적 메서드이며 클래스 속성에만 접근합니다.
    - `setUp`: 테스트마다 실행되는 인스턴스 메서드이며 `self`로 인스턴스 속성에 접근합니다.

**크롤러와 테스트 결합**: 무작위 링크를 따라가며 페이지 10개에 대해 연속으로 검사하는 예제입니다.

- 실제 테스트 메서드는 `test_PageProperties` 하나이고, `titleMatchesURL`, `contentExists`, `getNextLink`는 보조 함수입니다.
- 페이지마다 한 번만 요청하고, 메모리에 너무 많은 정보를 쌓지 않도록 주의합니다.
- `titleMatchesURL`이 불리언 대신 실제 값(페이지 제목, URL 제목)을 반환하는 이유는 실패 메시지 때문입니다. `assertTrue`는 False is not true만 알려주지만, `assertEqual`은 어떤 두 값이 달랐는지 보여줍니다. 예제에서는 리다이렉트 때문에 URL 제목과 실제 제목이 달라진 경우를 바로 파악할 수 있었습니다.

## 18.3 셀레니움을 사용한 테스트

셀레니움은 원래 웹사이트 테스트용으로 만들어진 도구라 자바스크립트가 많은 사이트도 다룰 수 있습니다.

- 테스트를 꼭 클래스 안에 넣을 필요가 없고, 파이썬 기본 `assert` 문으로 간단히 검증할 수 있습니다.
- 통과하면 아무 출력이 없고, 실패할 때만 메시지가 나옵니다.

### 18.3.1 사이트 조작

일반 스크레이퍼는 사이트를 지나가며 읽기만 하지만, 셀레니움은 입력, 클릭 등 사람이 브라우저에서 하는 행동을 실제로 수행합니다. 그래서 깨진 폼이나 잘못된 자바스크립트처럼 방문자를 방해하는 문제를 찾아낼 수 있습니다.

- **요소(element)**: `find_element`로 얻은 객체에 `click`, `click_and_hold`, `release`, `double_click`, `send_keys` 같은 행동을 취합니다.
- **액션 체인(ActionChains)**: 여러 행동을 묶어 두었다가 `perform()` 호출 시 순서대로 실행합니다. 기능상으로는 요소에 직접 호출하는 것과 같습니다.
- **폼 예제**: 이름 필드 두 개에 값을 넣고 제출하는 방법을 두 가지로 보여줍니다.
    - 방법 1: 각 필드에 `send_keys` 후 제출 버튼 `click`
    - 방법 2: 액션 체인으로 필드 클릭과 입력을 이어 붙이고 마지막에 Enter 키 전송
    - 결과는 같지만, 같은 결과를 여러 경로로 만들 수 있다는 점을 보여줍니다. (역자 주: 두 방법을 동시에 실행하면 오류가 나므로 하나만 남기고 실행)

**드래그 앤 드롭**

- `ActionChains(driver).drag_and_drop(소스, 대상).perform()`으로 처리합니다.
- 예제는 `setUp`에서 헤드리스 크롬을 띄우고 `tearDown`에서 닫는 unittest 구조이며, 드래그 후 메시지가 봇이 아님을 확인하는 문구로 바뀌는지 `assertEqual`로 검증합니다.
- 드래그 방식 CAPTCHA는 대부분 아주 단순한 과제라 봇도 쉽게 통과할 수 있다는 점을 짚습니다.

**스크린샷 찍기**

- `driver.get_screenshot_as_file(경로)`로 테스트 중간 화면을 이미지로 남길 수 있습니다.
- 저장할 폴더는 미리 만들어 두어야 합니다.

## 실습할 때 참고할 점

- 책 앞부분의 `driver.find_element_by_name(...)`은 셀레니움 4에서 제거되었습니다. 뒤 예제처럼 `find_element(By.NAME, ...)` 형태를 써야 합니다.
- 셀레니움 4.6 이상은 Selenium Manager가 드라이버를 자동으로 관리하므로 `webdriver_manager` 없이 `webdriver.Chrome(options=...)`만으로도 대부분 동작합니다.
- 위키백과 예제는 http로 적혀 있지만 실제로는 https로 리다이렉트되므로, URL 비교 로직에서 이 차이를 염두에 두는 게 좋습니다.
