### **1. 웹 스크레이핑의 기본 흐름**

웹 스크레이핑은 웹 서버에 페이지를 요청하고, 받은 HTML에서 원하는 정보를 추출하는 과정이다.

`웹 서버에 요청 → HTML 응답 → HTML 분석 → 원하는 데이터 추출`

브라우저는 HTML뿐 아니라 CSS, JavaScript, 이미지까지 처리하지만, 기본적인 스크레이퍼에서는 우선 **HTML을 가져오고 분석하는 것**에 집중한다.

---

### **2. urllib**

파이썬에서 웹 서버에 요청하여 HTML을 가져올 때 사용하는 라이브러리다.

- `urlopen()` : URL에 접속하여 데이터를 가져옴
- `read()` : 받아온 HTML 내용을 읽음
- HTML뿐 아니라 이미지 등 다른 웹 자원에도 접근 가능

즉, **urllib의 역할 = 웹에서 데이터를 가져오는 것**

---

### **3. BeautifulSoup**

가져온 HTML을 분석하고 필요한 정보를 추출하기 위한 라이브러리다.

BeautifulSoup은 HTML을 **트리 구조**로 변환하기 때문에 `<h1>`, `<body>`, `<div>` 같은 태그를 쉽게 탐색할 수 있다.

즉,

- **urllib → HTML 가져오기**
- **BeautifulSoup → HTML 분석 및 데이터 추출**

이 차이가 핵심이다.

---

### **4. HTML 파서**

BeautifulSoup은 HTML을 분석할 때 파서(Parser)를 사용한다.

- `html.parser` : 파이썬 기본 제공, 별도 설치 필요 없음
- `lxml` : 빠르고 잘못 작성된 HTML 처리에 강함
- `html5lib` : HTML 오류 복구에 강하지만 상대적으로 느림

웹 스크레이핑에서는 파서의 실행 속도보다 **네트워크 통신 시간이 더 큰 비중을 차지하는 경우가 많기 때문에**, 지나친 최적화보다는 안정성과 가독성이 중요하다.

---

### **5. 가상환경**

프로젝트마다 사용하는 라이브러리를 독립적으로 관리하기 위한 환경이다.

프로젝트별로 라이브러리 버전이 다를 수 있기 때문에 가상환경을 사용하면 **라이브러리 충돌을 방지**할 수 있다.

---

### **6. 예외 처리**

웹은 항상 정상적으로 동작하지 않으므로 스크레이퍼에서는 예외 처리가 중요하다.

- `HTTPError` : 서버가 404, 500 등의 HTTP 오류를 반환
- `URLError` : 서버를 찾지 못하거나 URL/연결 자체에 문제가 있음
- `AttributeError` : HTML은 가져왔지만 예상했던 태그가 존재하지 않는 경우 발생 가능

특히 **페이지를 정상적으로 가져왔다고 해서 원하는 데이터까지 반드시 존재하는 것은 아니다.** 사이트의 HTML 구조가 바뀌거나 특정 태그가 사라질 수도 있기 때문이다.
