## 도커 기본 개념

- 도커는 리눅스 컨테이너에 여러 기능을 추가해 애플리케이션을 컨테이너로 쉽게 쓸 수 있게 만든 **오픈소스 프로젝트**입니다.
- **Go 언어**로 작성됐고, **2013년 3월** 첫 릴리스 이후 계속 개발 중입니다.
- 관련 프로젝트로 Docker Compose, Private Registry, Docker Hub, Docker for Desktop 등이 있지만, 보통 도커라고 하면 **도커 엔진**을 의미합니다.
- 도커 엔진은 컨테이너를 생성하고 관리하는 주체이며 도커의 주 프로젝트입니다. 나머지 프로젝트는 엔진을 효율적으로 쓰기 위한 것이므로, 도커 엔진 사용법이 모든 것의 첫걸음입니다.

## 1.1 가상 머신 vs 도커 컨테이너

**가상 머신**

- 하이퍼바이저로 여러 OS를 하나의 호스트에서 생성해 사용합니다. 이렇게 생성된 OS를 게스트 OS라 하며, 각각 완전히 독립된 공간과 자원을 할당받습니다.
- 대표 도구: VirtualBox, VMware
- 단점 1: 자원 가상화 시 반드시 하이퍼바이저를 거치므로 **성능 손실**이 발생합니다.
- 단점 2: 게스트 OS용 라이브러리와 커널을 모두 포함해서 **이미지가 수 GB로 커지고** 배포가 부담스럽습니다.

**도커 컨테이너**

- 리눅스 자체 기능인 **chroot, namespace, cgroup**으로 **프로세스 단위의 격리 환경**을 만듭니다. 그래서 성능 손실이 거의 없습니다.
- 커널은 **호스트의 커널을 공유**하고, 컨테이너 안에는 앱 구동에 필요한 라이브러리와 실행 파일만 존재합니다.
- 결과적으로 이미지 용량이 작고 배포가 빠릅니다.

## 1.2 도커를 시작해야 하는 이유

컨테이너 도구는 CRI-O, Podman 등도 있지만 도커가 가장 보편적이고, 쿠버네티스 등 여러 프로젝트에 큰 영향을 줬습니다.

1. **개발과 배포가 편해짐**
    - 컨테이너는 호스트 OS 위의 격리된 공간이라, 특별한 권한을 주지 않는 한 내부에서 무엇을 해도 호스트 OS에 영향이 없습니다.
    - 작업 결과를 **도커 이미지**로 패키징해 운영 서버에 전달하면 끝이고, 의존성 걱정이 없습니다. 즉 개발/운영 환경 통합이 가능합니다.
    - 이미지는 커널을 포함하지 않아 작고, **레이어 단위**로 구성되어 중복 레이어를 재사용하므로 배포가 빠릅니다. (2.3절에서 상세)
2. **독립성과 확장성이 높아짐**
    - 모놀리스: 여러 모듈이 하나의 프로그램 안에서 동작. 서비스가 커질수록 확장성과 유연성이 떨어집니다.
    - 마이크로서비스: 모듈을 독립적으로 구성해 언어에 종속되지 않고 변화에 빠르게 대응합니다.
    - 컨테이너는 수 초 내 생성과 시작이 가능해 마이크로서비스에서 가장 많이 쓰입니다. 예를 들어 부하 시 웹 서버 컨테이너만 늘리고, 웹 서버와 DB 이미지 버전을 독립적으로 관리할 수 있습니다.
    - 실무에서는 직접 구현보다 **도커 스웜, 쿠버네티스 같은 오케스트레이션 플랫폼**을 사용합니다.
3. **컨테이너 기술을 쉽게 학습할 수 있음**
    - 모든 컨테이너 기술이 도커에 종속되는 것은 아닙니다.
    - 그래도 2013년부터 개발되어 성숙도와 편의성이 뛰어나고, 초창기 사실상 표준이었기 때문에 생태계 전반을 이해하기 좋습니다.

## 1.3 도커 엔진 설치

- 도커는 Go로 구현된 **libcontainer**(리눅스 컨테이너 제어 API)를 사용해 대부분의 리눅스에서 동작합니다.
- 윈도우 10, macOS 10.10.3 Yosemite 이전 버전은 별도의 가상화 공간이 필요합니다.
- **도커 CE**(Community Edition): 무료, 별도 기술 지원은 없음. 엔터프라이즈 지원이 필요하면 Mirantis Container Runtime을 고려합니다.
- 핵심 기능은 엔진 버전과 관계없이 거의 같습니다. 최신 버전은 불안정할 수 있으니 **어느 정도 시간이 지난 안정 버전 권장**합니다.

**리눅스 설치 조건 3가지**

- 지원 기간 내 배포판일 것
- 64비트 리눅스일 것 (32비트는 비권장)
- sudo 또는 root 권한으로 설치할 것

**기타**

- `get.docker.com` 설치 스크립트로 간편 설치가 가능하지만, 신뢰할 수 없는 셸 스크립트 실행은 좋은 습관이 아닙니다.
- 설치 확인 명령어: `docker info`
