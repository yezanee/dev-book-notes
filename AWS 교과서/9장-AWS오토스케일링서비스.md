## 9.1 스케일링 기본 개념

**스케일링(scaling)**: IT 자원을 확장하거나 축소하는 기능. 사용량이 고정적이지 않고 특정 상황(이벤트, 시간대)에 따라 변동되기 때문에 필요합니다.

- 스케일링을 통해 IT 자원의 **고가용성**과 **내결함성**을 확보

### 스케일링의 두 종류

| 구분 | 방향 | 세부 동작 |
| --- | --- | --- |
| **수직 스케일링** (vertical) | 자원의 **용량**(성능) 조정 | 스케일 업(고성능 교체) / 스케일 다운(저성능 교체) |
| **수평 스케일링** (horizontal) | 자원의 **수량** 조정 | 스케일 아웃(대수 증가) / 스케일 인(대수 감소) |

<br>

## 9.2 AWS 오토 스케일링 서비스 개념

**AWS 오토 스케일링**: 클라우드 자원을 **동적으로** 확장·축소하는 서비스. 수동 스케일링은 부하 예측이 어렵고 번거롭기 때문에, 온디맨드 특성을 활용해 자동으로 대응합니다.

- 적용 대상: **Amazon EC2**, ECS, DynamoDB 테이블/인덱스, Aurora 복제본 등
- 책에서는 **Amazon EC2 오토 스케일링**을 중심으로 다룸 → EC2에 대한 **수평 스케일링**을 동적으로 수행

### 구성 요소 3가지

| 구성 요소 | 역할 |
| --- | --- |
| **그룹** | 최소/최대/최초 요구 인스턴스 수를 지정하는 논리적 단위 |
| **구성(시작) 템플릿** | AMI, 인스턴스 유형, 키 페어, 보안 그룹 등 인스턴스 정의 |
| **조정 옵션** | 그룹 크기를 조정하는 방법(수동/동적/예약/예측) |

### 인스턴스 수명 주기

일반 EC2와 다른 수명 주기 보유: **대기 중 → 실행 중 → (로드밸런서 등록) → 종료 중 → 종료됨**

- **확장 이벤트**: 수동 증가 / 조정 정책에 의한 자동 증가 / 예약된 작업에 의한 증가
- **축소 이벤트**: 수동 감소 / 조정 정책에 의한 자동 감소 / 예약된 작업에 의한 감소
- **드레이닝(draining)**: 종료 대상 인스턴스를 즉시 삭제하지 않고 처리 중인 요청을 마무리할 시간을 부여하는 대기 상태 (새 연결은 받지 않음)

### 조정 옵션 5가지

1. **인스턴스를 일정한 수로 유지**: 헬스 체크 실패 시 비정상 인스턴스 종료 + 새 인스턴스로 대체
2. **수동 조정**: 최대/최소 용량을 직접 변경
3. **동적 조정**: 트래픽 변화에 따라 자동 조정
    - 대상 추적 조정 (목표 지표값 유지, 예: CPU 50%)
    - 단계 조정 (임곗값 초과 정도에 따라 단계별 조정)
    - 단순 조정 (초과 시 고정값만큼 조정)
4. **일정 기반 예약된 조정**: 특정 시간/날짜에 미리 용량 조정
5. **트래픽 패턴 기반 예측 조정**: 과거 데이터로 패턴을 예측해 자동 조정

### 요금

오토 스케일링 자체는 **무료**. 실제 사용한 **EC2 인스턴스**와 **CloudWatch 경보** 요금만 발생 (프리 티어 한도 내면 추가 요금 없음).

## 9.3 실습: Amazon EC2 오토 스케일링 구성하기

### 실습 목표

특정 이벤트(CPU 부하)를 발생시켜 동적 조정을 통해 인스턴스가 자동으로 확장·축소되는 동작을 직접 확인

### 실습 전체 흐름

```
① CloudFormation으로 기본 인프라 배포
② 기본 인프라 환경 검증
③ EC2 시작 템플릿 생성
④ 오토 스케일링 그룹 생성 및 확장/축소 정책 구성
⑤ CPU 부하 발생 → 스케일 아웃 확인
⑥ 부하 해소 → 스케일 인 확인
⑦ 실습 자원 전체 삭제
```

### ① CloudFormation으로 기본 인프라 배포

YAML 템플릿 URL 입력만으로 VPC(CH9-VPC), 퍼블릭 서브넷 2개(가용 영역 분산), ALB, 보안 그룹, 초기 EC2(MyEC2) 등을 자동 생성. IAM 리소스 생성 승인 체크 필요.

### ② 기본 인프라 환경 검증

MyEC2에 SSH 접속 → AWS CLI, ApacheBench(ab) 툴 설치 확인 → ALB DNS로 통신 테스트(현재 타깃 없어 503 정상)

### ③ EC2 시작 템플릿 생성 (핵심)

- AMI: Amazon Linux 2023, 인스턴스 유형: t3.micro
- 키 페어, 기존 보안 그룹 지정
- **세부 CloudWatch 모니터링 활성화**
- **메타데이터 액세스: 활성, 버전 V1 및 V2**
- **사용자 데이터(User Data)**: 부팅 시 자동 실행되는 스크립트
→ 새 인스턴스가 뜨자마자 웹 서버 설치·설정·헬스체크 준비 완료 상태가 됨
    
    ```bash
    yum install php8.3 httpd htop tmux -ysystemctl start httpd && systemctl enable httpdecho "<h1>...Web Server</h1>" > /var/www/html/index.htmlecho "1" > /var/www/html/HealthCheck.txtcurl -o /var/www/html/load.php ...   # CPU 부하 유발용 스크립트
    ```
    

### ④ 오토 스케일링 그룹 생성 및 정책 구성

**그룹 설정**

- 이름: FirstEC2ASG, VPC/서브넷: CH9-VPC의 두 가용 영역
- 로드 밸런싱: 기존 ALB(ALB-TG)에 연결
- 상태 확인: **ELB 상태 확인 켜기**, 유예 기간 60초
- 그룹 크기: 원하는 용량 1 / 최소 1 / 최대 4

**확장 정책 (Scale Out Policy)** — 대상 추적 조정

- 평균 CPU 사용률 **80%** 초과 시 자동 확장
- 확대 정책만 생성(축소 비활성화 체크)

**종료 정책 수립**

- 오토 스케일링 그룹 편집 → 종료 정책을 **최신 인스턴스**로 지정, 기본 휴지 기간 180초(드레이닝)

**축소 정책 (Scale In Policy)** — 단순 조정

- CloudWatch 경보 `ASG-CPU`: CPU 사용률 **10% 미만**이 2분 내 2회 연속 시 트리거
- 트리거되면 인스턴스 1대 제거, 대기 60초

**CloudWatch 대시보드(MyASG) 구성**

- 스케일 아웃/인 경보 2개 + `GroupInServiceInstances`(현재 인스턴스 수) 지표를 대시보드에 추가해 한눈에 모니터링

### ⑤ CPU 부하 발생 → 스케일 아웃 확인

1. WebServers 인스턴스에서 `htop`으로 CPU 상태 모니터링
2. `ab -n 5000 -c 100 http://$ALB/load.php` 로 반복 요청 → CPU 사용률 100% 근접
3. **3분 내 평균 80% 초과** → CloudWatch 경보 발동 → 인스턴스 **1대씩 순차적으로 2대 추가**되어 **총 3대**로 확장
4. ALB 대상 그룹(ALB-TG)에 새 인스턴스 자동 등록 → curl 반복 시 3개의 서로 다른 프라이빗 IP로 부하 분산되는 것 확인
5. 대시보드에서 `GroupInServiceInstances` 1→3 증가 그래프 확인

### ⑥ 부하 해소 → 스케일 인 확인

1. 부하 생성 명령 중단 → CPU 사용률이 자연스럽게 0%에 근접
2. **2분 내 CPU 평균 10% 미만이 2회 연속** → Scale In 경보 발동
3. 종료 정책(최신 인스턴스 우선)에 따라 **2대가 순차 종료**, 최초 인스턴스 1대만 잔존
4. 인스턴스 상태가 "종료됨"으로 전환, ALB는 남은 1대로만 트래픽 전달
5. 대시보드에서 `GroupInServiceInstances` 3→1 감소 그래프 확인

### ⑦ 실습 자원 삭제

1. CloudWatch **지표** 삭제 (그래프에 추가된 지표 제거)
2. CloudWatch **대시보드(MyASG)** 삭제
3. (이어서 오토 스케일링 그룹, 시작 템플릿, CloudFormation 스택 등 전체 인프라 삭제로 마무리)

## 핵심 요약 한 줄

> **CPU 사용률(지표)을 CloudWatch가 감시 → 임곗값 초과/미달 시 경보 발동 → 오토 스케일링 그룹이 정책에 따라 인스턴스를 자동 증감 → ALB가 새/삭제된 인스턴스에 맞춰 트래픽을 자동 재분배**

이 사이클이 트래픽에 맞춰 자원이 자동으로 늘고 줄어드는 클라우드 컴퓨팅의 핵심 동작 원리이며, 실무에서는 여기에 알림(SNS/Slack), 예약/예측 조정, 다중 가용 영역 고가용성 설계 등이 추가로 결합되어 운영됩니다.
